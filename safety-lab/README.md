# Safety and Alignment Lab

An interactive course on **what a safety claim is worth**, built around

> Yuntao Bai, Saurav Kadavath, Sandipan Kundu, Amanda Askell, Jackson Kernion, Andy Jones and others,
> *Constitutional AI: Harmlessness from AI Feedback*, arXiv:2212.08073 [cs.CL] / Anthropic, 2022,

together with

> Yuntao Bai, Andy Jones, Kamal Ndousse, Amanda Askell, Anna Chen, Nova DasSarma and others,
> *Training a Helpful and Harmless Assistant with Reinforcement Learning from Human Feedback*,
> arXiv:2204.05862 [cs.CL] / Anthropic, 2022;

> Ethan Perez, Saffron Huang, Francis Song, Trevor Cai, Roman Ring, John Aslanides and others,
> *Red Teaming Language Models with Language Models*, arXiv:2202.03286 [cs.CL] / EMNLP 2022;

> Evan Hubinger, Carson Denison, Jesse Mu, Mike Lambert, Meg Tong, Monte MacDiarmid and others,
> *Sleeper Agents: Training Deceptive LLMs that Persist Through Safety Training*,
> arXiv:2401.05566 [cs.LG] / ICML 2024;

> Mrinank Sharma, Meg Tong, Tomasz Korbak, David Duvenaud, Amanda Askell, Samuel R. Bowman and others,
> *Towards Understanding Sycophancy in Language Models*, arXiv:2310.13548 [cs.CL] / ICLR 2024;

and

> Nicholas Carlini, Florian Tramer, Eric Wallace, Matthew Jagielski, Ariel Herbert-Voss, Katherine Lee and others,
> *Extracting Training Data from Large Language Models*, arXiv:2012.07805 [cs.CR] / USENIX Security 2021.

The site is a real learning environment: a source-mapped curriculum, seven laboratories that run real algorithms in the
browser *and* from the terminal, a glossary whose dependencies are a checked directed acyclic graph, an equation
reference with derivations and worked examples, and a graded assessment bank.

> **Everything here is a teaching instrument.** The exchanges, the attacks, the label sheets, the questions and the
> training records are generated by this site's own code. The "assistant" that answers is a table of responses and a
> rule that names the principle violated; the "safety classifier" is a least-squares fit over cue features; the
> "attacker" is a seeded sampler over a taxonomy; the "language model" the extractor queries is a per-record
> probability set by how often that record was seen. No model, dataset or example is downloaded, and no data leaves
> the browser.

## Quick start

```bash
npm install          # from the workspace root, or in this directory
npm run dev          # http://localhost:5173
```

| Command | What it does |
| --- | --- |
| `npm run dev` | Vite dev server with hot reloading |
| `npm run build` | Type-check (`tsc -b`) then produce a static bundle in `dist/` |
| `npm run preview` | Serve the production build locally |
| `npm run typecheck` | Type-check only |
| `npm test` | Vitest unit, content, screen and page tests (203 tests) |
| `npm run lab -- <id\|all>` | The same laboratory, from the terminal — see below |
| `npm run test:e2e` | Playwright browser tests, including the accessibility audit (55 tests) |
| `npm run lint` | Oxlint |

The production build is a static bundle: `dist/` can be served by any static host.
There is no backend, no API key and no network call at runtime.

### The laboratories without a browser

```bash
npm run --silent lab -- all                 # every laboratory, at the default scenario
npm run --silent lab -- sleeper             # one of them
npm run --silent lab -- privacy --csv > privacy.csv
npm run --silent lab -- redteam --seed 11 --json
npm run --silent lab -- --list
```

`tools/run-lab.mjs` imports the functions in `src/core` and the scenario in `src/content/labDefaults.ts` — the same file
every screen reads its starting slider values from — so the terminal prints the numbers the page shows rather than a
second opinion about them. Where a screen has a toggle rather than a slider (which critic is answering, which label
sheet the team wrote, which of the two attackers is searching) the runner prints **both**, so the comparison the screen
draws is in the output rather than in the default. `--csv` emits `lab,kind,metric,value,note` rows; `--json` one object
per laboratory.

## What is in the course

### The curriculum (5 modules, 14 lessons)

| Module | Lessons | Source |
| --- | --- | --- |
| **Harmlessness from AI Feedback** | The critique-and-revise loop · The judge · What a claim is worth · The two rounds · The critic that sees what it cannot | Bai et al. (constitutional) §2, §3, §5; Bai et al. (HH) §3, §6 |
| **Red Teaming** | The attack · The taxonomy · The search budget | Perez et al. §3; Bai et al. (HH) §2 |
| **Cued Behaviour** | The cue nobody asked about | Hubinger et al. §2, §5 |
| **Sycophancy** | Agreeing with the user · The mitigation · What consistency buys | Sharma et al. §1, §4; Bai et al. (HH) §2 |
| **Privacy** | Memorisation · Who can tell | Carlini et al. §1, §3, §4 |

Every lesson names the section of the paper it was written from, and the test suite refuses a lesson that cites a
section which is not in the source map. Each one also deep-links into the laboratory view that shows its numbers, and
the link is checked from both ends: the content tests refuse a lesson that asks for a view a screen does not have, and
the screen tests mount every view at its own URL.

### The seven laboratories

| Lab | What you can change | What you can measure |
| --- | --- | --- |
| **A · The constitution** | The exchanges, how often the model complies, the judge's error rate, the cases the two critics are asked about, the seed | The harm before and after the loop, the responses changed, those still useful, the critiques per change, the judge's agreement with the labels, and the two critics against each other — recall, harm removed, cost and the category each one is blind to |
| **B · The two rounds** | The demonstrations, how often the labels pick the helpful answer, the learning rate, the steps, the weight on helpfulness, the seed | Where each round lands on the two axes, the movement the preference round made, the residual it left, the mean of each cluster in the pool, every step of the second round, and the weight at which the two rounds change places |
| **C · Red teaming** | The attacks, how often the model complies, the failures on the board, the largest budget, the runs averaged per point, the seed, which attacker | The attack success rate, the coverage of the taxonomy, the distinct findings, the other attacker at the same budget, the even-spending ideal, the guided against the unguided hunt and what it wasted, the budget for nine failures in ten and what one more attempt buys |
| **D · The cued behaviour** | Which label sheet the team wrote, the examples, the training size, the harmful rate, the share of that harm riding on the cue, the cue's share of harmless answers, the seed | The cued harm caught, the weight the fit gave the cue it was handed, the harm an evaluation that never fires the cue reports against the harm there is, the under-count, the cut it was judged at, the false alarms on clean answers, and what labelling the cue buys at every share |
| **E · The consistent labeler** | The looks per question, the lean toward agreeing, the consistency, how often the user is right, the questions, the seed | The repeat-agreement number and the sampled rate under it, what the reward model is handed, the panel's worth in independent looks, the policy's agreement and its accuracy, agreement between two labelers at three consistencies, and the majority of a panel of looks |
| **F · Sycophancy** | The questions, the seed | The flip rate, the rate with the challenge in the prompt, the number of points between them, and the rate as the sample grows — with the questions that flipped, and what the challenge did to each. The terminal adds how every answer falls across the three probes |
| **G · Privacy** | The records the prefix attack is run over, the prefix the attacker has, the guesses per record, the candidates, the share of members duplicated, the most copies, the share of outsiders that resemble a member, the queries per candidate, the seed | The exposure of the training set, the records recovered and the guesses spent, the membership attack's AUC, hit rate, false-alarm rate and precision, the same corpus without its near-duplicates, what one query buys against sixty-four, and the extraction rate against the duplication rate |

Laboratory D is the one worth reading carefully. Its classifier is exact about every harm it was told about and silent
about the rest, and the silence is not a mistake in the fit: a cue the label sheet does not name never gets a column,
so the harm that rides on it is not mis-classified — it is never counted. The screen prints the reported harm and the
harm there is side by side, and the runner prints both label sheets, because the difference between a measurement that
failed and a measurement that was never run is the whole lesson.

### The rest of the course

- **Practice** — 28 questions with per-option feedback, worked explanations and source citations.
- **Glossary** — 23 terms, each with a plain-language definition and the terms that should be understood first. The
  dependency graph is checked for cycles.
- **Equations** — 13 results with the source, the plain-language meaning, every symbol, the assumptions, a derivation
  and a worked example. Every worked example is computed from the code in this repository, not transcribed from a
  paper.
- **Sources** — six papers and the shared core they build on, each with the licence it was verified under, and the
  section map of each source.

## The rule this course follows

**Every number is computed, and nothing is faked.**

The algorithms live in `src/core/` as pure functions with no DOM and no framework. They are unit-tested in Node,
without a browser, and the interface renders what those functions return. There are no stored result arrays anywhere in
the repository.

Three things beyond that are checked rather than asserted:

- **Every screen renders, at every view it declares** (`src/components/lab/lab.test.tsx`), including the URL a lesson
  links to, and no view is allowed to print `NaN`, `undefined`, `Infinity` or `[object …]`.
- **The registry cannot drift** (`src/content/content.test.ts`): a lesson that names a laboratory or a view that does
  not exist fails, and so does a screen whose option list no longer matches the one the registry advertises. The
  landing and lesson pages print their counts from the same lists the routes are built from (`src/pages/pages.test.tsx`),
  which is why no page can claim four laboratories while seven exist.
- **The prose is a test case.** Where a screen or an equation claims a number — that the under-count in laboratory D is
  a property of the evaluation set rather than of the fit, that a majority of three independent looks is better than
  one while three looks by one consistent labeler are not, that the residual of the preference round halves with each
  step — the claim is asserted in `src/core/*.test.ts` at the tolerance the screen prints.

### What the instruments measure

A harmlessness score is the opinion of a judge, measured on a sample, against a taxonomy. A backdoor is a conditional
behaviour, measured against the label sheet that named the condition. A consistency number is an agreement rate,
measured against the number of independent looks it actually contains. An exposure is a recovery rate, measured against
the length of the prefix the attacker already had. This course makes each of those pairs a number on the same screen,
because a safety claim that reports only the first half of each pair is a claim about a benchmark rather than about a
model.

### Where the honesty ends

What this is **not**: a model, a claim about any real assistant's harmlessness rate, or a reproduction of any number in
any of the six papers. The biases are planted — the corpus in laboratory D is generated with the cued share of harm set
by a slider, the labeler in laboratory E agrees at a rate typed into a box, and the training set in laboratory G
contains duplicates because the scenario said to put them there. That is what makes each effect measurable rather than
merely suspected, and every screen says so in its own text.

## Project layout

```
src/
  core/            the algorithms — pure functions, no React, no DOM
    constitution.ts  the principles, the critique, the revision, the two critics, the judge's agreement
    alignment.ts     the two rounds, the residual, the utility of a weighting, the crossover
    redteam.ts       the attacker, the success rate, the coverage, the search budget
    sleeper.ts       the cued corpus, the fitted classifier, the cut, the under-count, the wrong-cue control
    preference.ts    the labeler, the repeat agreement, the panel's worth, the majority of looks
    memorisation.ts  the trained probabilities, the duplication curve, the membership attack
    measures.ts      the flip rate, the mitigation, the extraction attack, the exposure
  content/         the course: curriculum, labs, glossary, quiz, equations, sources
    labDefaults.ts  the scenario each screen starts on, read by the browser and the runner
  components/lab/  the seven laboratories, one file each, plus the screen tests
  pages/           one file per route, plus the page tests
  test/            test setup
tools/
  run-lab.mjs      the same laboratories, from the terminal
  ts-resolver.mjs  lets Node import the TypeScript core directly
e2e/               Playwright specs, including the axe-core audit
docs/              sources and licensing
```

The shared interface layer — the primitives, the mathematics renderer, the charts, the shell and the progress provider —
lives in `@llm-materials/course-ui`, the numerical and statistical core in `@llm-materials/course-core`, and the
collection-wide catalogue in `@llm-materials/course-catalogue`. The rule is unchanged: **numbers are computed in
`src/core`, never in a component.**

## Accessibility

- An **axe-core audit** runs over twenty pages in the browser suite, in both the light and the dark theme, and fails the
  build on any `wcag2a`, `wcag2aa`, `wcag21a` or `wcag21aa` violation. Seven laboratory screens and three deep-linked
  views are in that list.
- Every tab strip implements the WAI-ARIA tab pattern; charts carry a name, a caption and a data-table alternative; the
  theme is applied before the first paint.
- `/` opens the course search and `Escape` closes it.
