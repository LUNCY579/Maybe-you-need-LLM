# Retrieval Lab

An interactive course on **finding the document that answers the question**, built around

> Patrick Lewis, Ethan Perez, Aleksandra Piktus and others,
> *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks*,
> arXiv:2005.11401 [cs.CL] / NeurIPS 2020,

together with the dense retriever of

> Vladimir Karpukhin, Barlas Oguz, Sewon Min and others,
> *Dense Passage Retrieval for Open-Domain Question Answering*,
> arXiv:2004.04906 [cs.CL] / EMNLP 2020;

the late interaction of

> Omar Khattab, Li Deng, Xinyu Yang and others,
> *ColBERT: Efficient and Effective Passage Search via Contextualized Late Interaction over BERT*,
> arXiv:2004.12832 [cs.IR] / SIGIR 2020;

and the position effect of

> Nelson F. Liu, Kevin Lin, John Hewitt and others,
> *Lost in the Middle: How Language Models Use Long Contexts*,
> arXiv:2307.03172 [cs.CL] / TACL 2024.

The site is a real learning environment: a source-mapped curriculum, four laboratories that run real algorithms, a
glossary whose dependencies are a checked directed acyclic graph, an equation reference with derivations and worked
examples, and a graded assessment bank.

> **Everything here is a teaching instrument.** The corpus is generated by this site's own code, and every question has
> exactly one correct document — so the recall of a retriever is a measurement and not an opinion. No dataset, index or
> trained model is downloaded, and no data leaves the browser.

## Quick start

```bash
npm install          # from the workspace root, or in this directory
npm run dev          # http://localhost:5173
```

| Command | What it does |
| --- | --- |
| `npm run dev` | Vite dev server with hot reloading |
| `npm run build` | Type-check (`tsc -b`) then produce a static bundle in `dist/` |
| `npm run preview` | Serve the production build locally |
| `npm run typecheck` | Type-check only |
| `npm test` | Vitest unit and content tests (87 tests) |
| `npm run test:e2e` | Playwright browser tests, including the accessibility audit |
| `npm run lint` | Oxlint |

The production build is a static bundle: `dist/` can be served by any static host.
There is no backend, no API key and no network call at runtime.

## What is in the course

### The curriculum (4 modules, 8 lessons)

| Module | Lessons | Source |
| --- | --- | --- |
| **Sparse Retrieval** | The lexical index · BM25 | Lewis et al. §2 |
| **Dense Retrieval** | The learned embedding · The contrastive objective | Karpukhin et al. §3, §4 |
| **Late Interaction** | The MaxSim score | Khattab et al. §3, §4 |
| **The Long Context** | The retrieval-augmented reader · Lost in the middle · What retrieval is for | Lewis et al. §1, §3, §3.1; Liu et al. §1, §3, §4 |

Every lesson names the section of the paper it was written from, and the test suite refuses a lesson that cites a
section which is not in the source map.

### The four laboratories

| Lab | What you can change | What you can measure |
| --- | --- | --- |
| **A · The sparse index** | The corpus size, k1, b | The number of postings, the distribution of the document frequency, the recall at k against a random ranking, and the BM25 scores of the best documents |
| **B · The dense retriever** | The corpus, the dimension, the steps, the temperature | The contrastive loss, the recall of the trained retriever against the lexical one, and the ranking it produces |
| **C · The late interaction** | The corpus, the dimension, the steps, the normalisation | The MaxSim score, the length bias of it, the ranking, and the number of vectors each index needs |
| **D · The long context** | The context length, the strength of the position prior, the temperature | The attention a document receives as it is moved through the context, and the long-context reader against the retrieval-augmented one |

Every retriever is trained **in the browser, from scratch**, every time a setting changes.

### The rest of the course

- **Practice** — 16 questions with per-option feedback, worked explanations and source citations.
- **Glossary** — 21 terms, each with a plain-language definition and the terms that should be understood first. The
  dependency graph is checked for cycles.
- **Equations** — 8 results with the source, the plain-language meaning, every symbol, the assumptions, a derivation
  and a worked example.
- **Sources** — every work cited, with the licence it was verified under, and the section map of each source.

## The rule this course follows

**Every number is computed, and nothing is faked.**

The algorithms live in `src/core/` as pure functions with no DOM and no framework. They are unit-tested in Node,
without a browser, and the interface renders what those functions return.

### Every answer is known

The corpus is built so that the questions and the answers use *different* words, which is the case the course is about.
Every question has exactly one correct document, so:

- the recall of a retriever is a measurement against a known answer, not an opinion;
- the random ranking gives the number to beat, and the laboratory draws it;
- the two retrievers are compared on the same questions, so the comparison is between the retrievers.

### The gradient is checked, not asserted

The contrastive objective is differentiated by the shared automatic-differentiation engine, and the test suite compares
the result against a central finite difference, component by component.

## Project layout

```
src/
  core/            the algorithms — pure functions, no React, no DOM
    corpus.ts       the corpus, the topics, the questions and their answers
    sparse.ts       the inverted index, BM25, the recall
    dense.ts        the dual encoder, the contrastive training, MaxSim
    context.ts      the position prior, the needle, the reader
  content/         the course: curriculum, glossary, quiz, equations, sources
  components/lab/  the four laboratories
  pages/           one file per route
  test/            test setup
e2e/               Playwright specs, including the axe-core audit
docs/              sources and licensing
```

The shared interface layer lives in `@llm-materials/course-ui`, the numerical core in `@llm-materials/course-core`, and
the collection-wide catalogue in `@llm-materials/course-catalogue`. The rule is unchanged: **numbers are computed in
`src/core`, never in a component.**

## Accessibility

- An **axe-core audit** runs over fourteen pages in the browser suite, in both the light and the dark theme, and fails
  the build on any `wcag2a`, `wcag2aa`, `wcag21a` or `wcag21aa` violation.
- Every tab strip implements the WAI-ARIA tab pattern; charts carry a name, a caption and a data-table alternative;
  the theme is applied before the first paint.
- `/` opens the course search and `Escape` closes it.
