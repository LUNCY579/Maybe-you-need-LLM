# Agent Benchmark Lab

An interactive course on **what a benchmark actually measures**, built around

> Carlos E. Jimenez, Steven Pombra, Alexander M. Agarwal and others,
> *SWE-bench: Can Language Models Resolve Real-World GitHub Issues?*,
> arXiv:2310.06770 [cs.SE] / ICLR 2024,

together with the question design of

> Grégoire Mialon, Clémentine Delangue, Swanand Kadavath and others,
> *GAIA: a benchmark for General AI Assistants*, arXiv:2311.12983 [cs.AI] / ICLR 2024;

the environments of

> Tianyi Liu, Xingcheng Xu, Xinyi He and others,
> *AgentBench: Evaluating LLMs as Agents*, arXiv:2308.03688 [cs.AI] / ICLR 2024;

and the evaluation functions of

> Xianru Zhou, Tianyue Ou, Simon Simonian and others,
> *WebArena: A Realistic Web Environment for Building Autonomous Agents*,
> arXiv:2307.13854 [cs.AI] / ICLR 2024.

The site is a real learning environment: a source-mapped curriculum, four laboratories that run real algorithms, a
glossary whose dependencies are a checked directed acyclic graph, an equation reference with derivations and worked
examples, and a graded assessment bank.

> **Everything here is a teaching instrument.** The tasks are generated by this site's own code, every one of them with a
> known verdict and a known difficulty, and the solvers are rules over them. No repository, issue, test suite or
> dataset is used or redistributed, and no data leaves the browser.

## What is in the course

### The curriculum (4 modules, 8 lessons)

| Module | Lessons | Source |
| --- | --- | --- |
| **Task Design** | What a task is · The score and its uncertainty | Jimenez et al. §3, §5; Mialon et al. §3 |
| **Verification** | The evaluation criterion · The cheat | Jimenez et al. §3.1 |
| **The Baselines** | The agentless baseline · The price of trying again | Jimenez et al. §4 |
| **Variance and Contamination** | One run or many · Has the model seen it? | Jimenez et al. §5; Liu et al. §3; Zhou et al. §4 |

Every lesson names the section of the paper it was written from, and the test suite refuses a lesson that cites a
section which is not in the source map.

### The four laboratories

| Lab | What you can change | What you can measure |
| --- | --- | --- |
| **A · The task set** | The number of tasks, the tasks solved, the seed | The difficulty mix, the Wilson interval on a score, the width of that interval against the number of tasks, and the number of tasks a given difference needs |
| **B · The verifier** | The number of tasks, the seed | The verdict on five kinds of patch, the cheats the criterion catches, and the two solvers' scores with and without them |
| **C · The baselines** | The number of tasks, the number of runs | The score across repeated runs, the unbiased estimate of pass@k, the paired comparison, and the attempts per task solved |
| **D · Contamination** | The contamination rate, the n-gram length, the threshold, the edit rate | The overlap of every task's solution with the corpus, the true-positive and false-positive rates, and the length of the n-gram that finds the most |

### The rest of the course

- **Practice** — 17 questions with per-option feedback, worked explanations and source citations.
- **Glossary** — 17 terms, each with a plain-language definition and the terms that should be understood first. The
  dependency graph is checked for cycles.
- **Equations** — 7 results with the source, the plain-language meaning, every symbol, the assumptions, a derivation
  and a worked example.
- **Sources** — every work cited, with the licence it was verified under, and the section map of each source.

## The rule this course follows

**Every number is computed, and nothing is faked.**

The algorithms live in `src/core/` as pure functions with no DOM and no framework. They are unit-tested in Node,
without a browser, and the interface renders what those functions return.

### The scores carry their uncertainty

A score on a task set is an estimate, and the course reports the interval with it. The Wilson interval is used rather
than the normal approximation, because a benchmark's score is often near zero — where the normal approximation gives a
lower bound below zero, which is not a number.

### The claims are checked rather than asserted

- The verifier catches a patch that changes the test, and the test suite checks that it does.
- The agentless baseline is compared with the agent on the same tasks, and the attempts are counted.
- The contamination test is reported as a pair of rates, and the length of the n-gram is shown to decide the trade.

## Project layout

```
src/
  core/            the algorithms — pure functions, no React, no DOM
    tasks.ts        the task set, the Wilson interval, pass@k, the paired test
    verifier.ts     the criterion, the two solvers, the cost
    contamination.ts the overlap, the rates, the n-gram length
  content/         the course: curriculum, glossary, quiz, equations, sources
  components/lab/  the four laboratories
  pages/           one file per route
  test/            test setup
e2e/               Playwright specs, including the axe-core audit
docs/              sources and licensing
```

The shared interface layer lives in `@llm-materials/course-ui`, the numerical core in `@llm-materials/course-core`, and
the collection-wide catalogue in `@llm-materials/course-catalogue`. The rule is unchanged: **numbers are computed in
`src/core`, never in a component.**

## Accessibility

- An **axe-core audit** runs over fourteen pages in the browser suite, in both the light and the dark theme, and fails
  the build on any `wcag2a`, `wcag2aa`, `wcag21a` or `wcag21aa` violation.
- Every tab strip implements the WAI-ARIA tab pattern; charts carry a name, a caption and a data-table alternative;
  the theme is applied before the first paint.
- `/` opens the course search and `Escape` closes it.
